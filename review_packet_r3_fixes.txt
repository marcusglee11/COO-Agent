6. DESIGN DECISIONS
================================================================================

6.1 DETERMINISTIC REPLAY
--------------------------------------------------------------------------------

CHALLENGE: Orchestrator uses non-deterministic sources:
- uuid.uuid4() for message IDs
- CURRENT_TIMESTAMP in SQLite for timestamps
- Potentially random LLM responses

SOLUTION:
1. Mock uuid.uuid4() with counter-based deterministic UUIDs
2. Mock ModelClient to return deterministic responses (hash-based)
3. Semantic DB comparison ignoring timestamp columns

RATIONALE:
- Mocking at the source ensures consistency
- Semantic comparison is more robust than byte-for-byte
- Allows minor timing variations without false negatives
- Maintains verification of actual data integrity

6.2 SNAPSHOT INTEGRITY
--------------------------------------------------------------------------------

CHALLENGE: Need to verify AMU0 hasn't been tampered with

SOLUTION:
- SHA256 hash manifest for each file
- Signature over manifest and context
- Strict verification before restore

RATIONALE:
- Hash verification is cryptographically secure
- Per-file hashing detects even single-byte corruption
- Signature ensures bundle authenticity
- Structure ready for production crypto integration

6.3 STRICT MODE ENFORCEMENT
--------------------------------------------------------------------------------

CHALLENGE: Prevent accidental governance approval in dev environment

SOLUTION:
- COO_STRICT_MODE environment variable
- Checked before critical state transitions
- Fails hard if not set

RATIONALE:
- Environment variables are standard for runtime config
- Explicit opt-in prevents accidents
- Clear separation between dev and production
- Easy to verify in deployment scripts

6.4 MOCK SIGNATURES
--------------------------------------------------------------------------------

DECISION: Use mock signature format for POC

FORMAT: SIG_{sha256_digest}_CEO_KEY

RATIONALE:
- Demonstrates signature workflow
- Tests signature verification logic
- Structure ready for real crypto
- Clearly identifiable as mock (contains "SIG_" prefix)

FUTURE: Replace with actual cryptographic signatures (e.g., Ed25519, RSA)
